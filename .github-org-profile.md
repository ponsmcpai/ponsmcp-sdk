## What this is

A **Model Context Protocol server + TypeScript SDK** that lets autonomous agents:

- **settle payments** in USDG on Robinhood Chain (4663) — with local policy checks before any key material is touched
- **pay for HTTP resources** through the HTTP 402 flow (`pons_pay_resource`)
- **research pons launches** — v1 metadata, v2 bonding-curve quotes, snipe-tax reads, launch feed, fee-escrow balances, graduation ranking
- **read & trade tokenized stocks** — 19 Robinhood Chain stock tokens (NVDA, AAPL, TSLA…) with live price/liquidity screening
- **send any token** — USDG, PONS, stocks, or native ETH, by ticker or address

**25 tools. Zero runtime dependencies.** Keccak, RLP, and secp256k1 are implemented in-repo and validated against standard vectors. The npm tarball is byte-identical to this source.

```bash
npm install -g @ponsmcp/sdk
ponsmcp          # stdio MCP server — plug into Claude, Cursor, or any MCP host
```

## The payment loop

```
quote → policy → sign (local, EIP-155) → broadcast → receipt → decoded transfers
```

A payment is *done* only when the receipt is `0x1` **and** the decoded USDG transfer matches token, recipient, and amount. Merchants re-verify with `pons_tx_status` — a client's hash is a claim, not proof.

## Design rules this org follows

1. **Keys never leave the runtime.** Browsers and consoles create and inspect intents — they never sign.
2. **Policy before signature.** Per-tx (100 USDG) and daily (1,000 USDG) caps are enforced before key material is used.
3. **Proof over claims.** Success = on-chain receipt with the exact transfer. Everything else is pending.
4. **No fabricated status.** The public status page runs live checks from the viewer's browser — including the failures.
5. **Honesty about the token.** $MCP is live at `0x15da2596F4C21227185466066Bf0f19d9D526B8a` on Robinhood Chain — verify the contract yourself, never trust a ticker alone.

## Integrating

```ts
import { PonsMCPClient } from "@ponsmcp/sdk";

const client = new PonsMCPClient({
  privateKey: process.env.PONSMCP_PRIVATE_KEY,
  policy: { maxPerTx: 100_000_000n, dailyLimit: 1_000_000_000n },
});

const r = await client.pay({ payTo: "0x…", amountUsd: "5.00" });
// r.ok → r.txHash, r.explorer, r.transfers
```

See [`ponsmcp-examples`](https://github.com/ponsmcpai/ponsmcp-examples) for the full loop, including a 402 merchant server in ~40 lines.

## Transparency

- Live on-chain status: [ponsmcp.com/status](https://ponsmcp.com/status) (real checks, from your browser)
- All payment examples enforce policy caps — read-only tools never need a key
- The bundler-style launch/snipe execution is deliberately **out of scope**; launch tools are read-only intelligence
